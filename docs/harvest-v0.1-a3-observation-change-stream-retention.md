# Harvest V0.1-A3 — Observation, Change Stream & Retention

Status: **Implementation-ready** (2026-11-08). Based on the completed A2 implementation and acceptance in develop. Work in **librecosta/harvest**, branch **develop** only. No production changes.

## Sources and scope

Read AGENTS.md and the existing A1 Engineering Baseline, A1-A, A1-B, A1-C, A1-P, A1/A2 acceptance reports and A2 implementation. A1-C is normative for consumer data and stream consistency; this document narrows the A3 deliverable.

Deliver the first durable acquisition result pipeline: the Worker commits typed, scoped observations under the existing Job/Attempt lease; Harvest retains last-known-good results, bounded meaningful history, and a commit-safe event stream; an authenticated consumer can query latest/history, incrementally replay and recover after its cursor has expired.

**Only a test-only compiled Provider** is used for real execution proof in A3. Production Web/Steam remain explicitly not_implemented until V0.1-B/C. Do not create GoFurry Site/Game tables or a new sync service. Preserve the A0/A1/A2 scheduling, network/proxy/permits and service lifecycle.

## 1. Result contract: multiple independently scoped segments

The existing provider.Result has a single Data blob and an Attempt-level State. Extend minimally with versioned Segments, or migrate the test fixture with a narrow typed adapter. Do not treat arbitrary JSON as successful production data.

- Attempt-level result states: succeeded, partial, failed, cancelled. Job terminal/retry logic remains owned by A1.
- Segment fields: canonical semantic scope (namespace, locale, source region, semantic egress region and capability-specific dimensions), output schema version, observed_at, state, bounded typed data, safe provenance/source marker and optionally upstream content version.
- Segment states: present, confirmed_empty, not_modified, unavailable, invalid, not_covered. Valid zero is not failure. Confirmed empty requires explicit source evidence of completeness. Not modified requires a prior valid current result.
- Success in one scope never clears another scope whose collection failed. Unknown/missing scope never means withdrawn. Partial completion must still preserve existing A1 retry behavior; no fake success for missing declared scopes.
- Canonicalize typed scope deterministically; forbid conflicting duplicates in the same completion, unsupported schema versions, namespace escapes and unjustified region mixing.
- Keep the A1 request parameter budget. Establish a separate bounded result-completion budget (initial candidates: 512 KiB per segment, 2 MiB per completion, at most 16 segments; per-capability lower limits). Do not raise all public/control endpoints to this body size. Data should be normalized values, not entire HTML/media/raw API archives.

## 2. PostgreSQL 18: additive, small schema

Explicit Goose migrations, sqlc + pgx SQL, no ORM and no migration at application startup. All entity IDs use Go 1.27 native UUIDv7 / PostgreSQL uuid; version counters and stream positions are not entity IDs. Add only what A3 actually consumes:

- harvest.observations: immutable UUID primary key; target/capability/output schema, canonical semantic scope and namespace, segment state, observed_at vs DB received_at, typed bounded data, stable content hash, nonsecret provenance, immutable Job/Attempt UUID lineage. No cascading reference to expiring Attempt/Job history.
- harvest.current_results: unique per (target, capability, schema, canonical scope and namespace), references the latest valid immutable observation; last-confirmed timestamp, content hash, semantic revision/change position. **Avoid storing the full JSON payload twice** in current and historical rows. The current referenced observation remains pinned by retention.
- harvest.change_heads: one durable stream key/authorization namespace with last committed bigint position, minimum available position and stream epoch. Position is incremented inside an ordinary transaction while holding the row lock; not generated by a sequence.
- harvest.change_events: composite primary key (stream key, position), action upsert/withdraw/sample, stable scoped entity identity, immutable observation reference or self-contained small tombstone, committed time. Unexpired event references pin required old observations.
- harvest.consumers: UUID primary key, named service-principal/allowed stream, ACK position, epoch, last activity and reset-required state. Operator provisions consumer explicitly; no auto-created consumer per poll.
- Small maintenance checkpoint only when necessary for bounded pruning; no generic distributed workflow or table-per-Provider.

Ensure safe indexes for scoped latest/history pagination, stream positions and retention. Test real migrations from A2 and a fresh database. Inspect EXPLAIN (ANALYZE, BUFFERS) on meaningful fixture counts, not just empty tables.

## 3. One atomic completion transaction

Preserve the existing A1/A2 completion endpoint and same-attempt receipt replay:
1. Lock Job, verify current Attempt/Worker/generation, valid lease, authorization, non-cancelled Job and versioned schema. Exact replay of an already accepted payload returns the prior durable receipt without new rows; a conflicting replay or stale generation is rejected.
2. Validate **every** segment (scope, schema, count, body size, provenance) before any mutation. Only present and confirmed_empty may replace a scoped current result; not_modified may update freshness on an already valid scoped result. unavailable/invalid/not_covered must not clear last-known-good.
3. Content-identical details: update lightweight confirmation freshness, not a duplicated large observation or change event. Changed details: immutable observation + current pointer + applicable change. Point-in-time numeric samples remain distinct even when value repeats; missing samples never get invented. Authoritative withdraw requires an explicit Provider policy, never inferred from a transient HTTP error.
4. In the **same PostgreSQL transaction**, commit Attempt/Job receipt/state, accepted observations, current projection and any emitted stream events. On SQL failure roll back all. Preserve partial-success semantics for independent scopes.

Standard lock order: Job -> Attempt -> scoped current/observations -> stream head(s) in lexical order -> events. Do not introduce a second scheduler, Worker or result-acceptance service.

## 4. Commit-ordered incremental feed

Do not assume UUIDv7, wall-clock timestamps, bigint sequence or auto-increment values are commit-order cursors.

An accepted result transaction emitting change events must lock the appropriate change_heads row FOR UPDATE, allocate consecutive positions there and commit its head update and events with the result/receipt. A competing writer to the same stream waits for commit/rollback; rollback leaves no committed gap. Multiple streams lock in deterministic order. The consumer cannot observe position N+1 as committed while N may still be pending.

Provide authenticated, versioned routes under /api/v1:
- GET /observations/current — latest successful scoped data, keyset pagination.
- GET /observations/history — bounded, optionally by target/capability/scope/time.
- GET /changes?stream=...&after=...&limit=... — ascending committed events with next cursor, head, min available, epoch, has_more (candidate 50 default / 200 hard maximum).
- GET /snapshots/current — documented baseline/live scan protocol.
- POST /consumers — operator-only enrollment or equally narrow CLI.
- POST /consumers/:id/ack — scoped, monotonic ACK, never greater than head. A consumer first durably commits its data and cursor **in its own database**, then ACKs. Reads alone never ACK.

Keep API routes in the existing internal/routers/url.go, groups in router.go and probes in health.go. Do not register an open/public raw fetch or proxy API. Worker completion stays authenticated and separate.

Events that reference historical observations must remain fetchable until event retention permits their removal. Withdraw must carry a complete immutable identity/tombstone, even after current data disappears. Explicit 410 cursor_expired for a cursor older than the retained stream, never a silent jump to head. Epoch, principal scope and stream identity are validated on every read.

## 5. Correct consumer snapshot recovery during concurrent writes

Avoid holding one long REPEATABLE READ PostgreSQL transaction open across numerous HTTP page requests or duplicating the entire database indefinitely.

Implement the A1-C **baseline-head + live keyset scan + replay** contract with an explicit correctness test:

1. At reset start capture committed head H, epoch and fixed authorization. Provide bounded reset token/deadline; retain events after H during the active reset within a capped budget. If event retention cannot cover the reset, abort it and require a fresh baseline.
2. Scan current results in immutable canonical identity order via keyset (not OFFSET). Include each row's **last event position/version**, even if the observed row is newer than H.
3. Consumer constructs a staging projection, not an in-place partial published dataset. After pages finish, replay events strictly after H. Apply an event to an entity only if its position is **newer** than that entity's staged version. A newer live snapshot row must not be overwritten by an older replay event. Withdraw tombstones remove entries; inserts missed because pagination passed their keys appear via replay.
4. At a definite committed head the consumer activates its staging dataset and durable cursor atomically, then ACKs separately. Reset expiry/stream pruning/permission change invalidates it explicitly.

Test concurrent insert, update, withdraw, recreated identity, an insertion before the page cursor and a snapshot row newer than first replay event. If another simpler algorithm is used, prove equivalent convergence and document it, rather than weakening tests.

This is Harvest acquisition data synchronization. **It is not the GoFurry CN -> INTL business sync.**

## 6. Storage, pruning and bounded operational cost

- Preserve last-known-good Observation while it is referenced as current; preserve any old Observation referenced by an unexpired replay event. Existing A1 Job/Attempt and A2 permit retention must continue to work.
- Do not archive full raw HTML, Steam response blobs, media or screenshots by default; optional raw snapshot storage remains deferred. Semantic detail changes are stored, unchanged scans only update freshness. Time-series samples can be kept at fixed frequency with bounded history.
- Initial *configurable* candidate horizons: raw point-in-time samples 30 days, change-event delivery about 14 days, Job/Attempt 30 days as already implemented; optional daily aggregation deferred unless clearly needed. Apply age and bounded row/byte limits, not unbounded append.
- Before pruning would cross an unacknowledged consumer cursor, mark it reset_required; subsequent old cursor reads return HTTP 410. Update min_available_position correctly: after == min_position-1 is valid, older expired. Do not wait forever for offline consumers.
- Run bounded short prune batches (candidate <=128); remove safe expired events before old unpinned observations, never delete active jobs/current snapshots or needed history through CASCADE. No long locks/large DELETE storms.
- Authenticated operations status reports bounded row/byte estimates, per-capability history, stream head/lag, expired consumers, prune state, and meaningful storage warnings; no credentials or raw payloads.

A2 measured **26.59 idle SQL statements/s** with three Workers, and **558.98 statements/s** under a test load of about 18.73 outbound requests/s. A3 must report incremental SQL statements, WAL growth, DB connections/waits, stream-head lock contention, API/submission p95 and memory/CPU; do not invent production SLA or introduce Redis/messaging merely to pass a synthetic benchmark.

## 7. Auth, lifecycle, Task and Docker

Reuse A1 service-principal roles and namespace access; consumer creation and ACK restricted to the owning principal/authorized streams. Do not leak a private target into the public namespace. Request/response field whitelisting, strict JSON v2 decoding and stable error codes; include meaningful 400/403/409/410/413/503 distinctions. A2 per-roundtrip permits and proxy safety remain unchanged.

Retain Fiber OnListen, OnPreShutdown, OnPostShutdown, readiness and bounded result submission pre-drain. Result accepted once before shutdown remains durable and replay-safe. No invisible env config. Keep Task and Compose, isolated disposable PostgreSQL 18, Linux/Windows checks and ARM64 image build.

## 8. Mandatory executed acceptance

1. Fresh PostgreSQL 18 + A2-to-A3 upgrade preserve Target, Schedule, Job, Worker and quota data. Goose/sqlc generated output reproducible; no implicit DDL.
2. Partial multi-scope test fixture: one locale succeeds and one fails without destroying previous good. Genuine numeric zero vs missing and confirmed_empty behavior are distinct.
3. Unchanged repeat detail scan generates no full duplicate data/change; changed value generates one new immutable Observation/current reference/change. Time-series repeated zeros remain samples.
4. Duplicate attempt completion replays old receipt with no duplicate observation/event. Conflicting replay, stale lease and cancellation cannot write.
5. Concurrent result commits to same stream are commit-ordered; rollback leaves no cursor gap; concurrent different streams do not deadlock.
6. Bounded cursor pagination and namespace filtering; consumer ACK monotonic and principal-scoped, never implicit on read.
7. Baseline/live snapshot + replay convergence under insert/update/withdraw while paging; newer snapshot vs older replay is safe; expired reset and old cursor return explicit error, not partial success.
8. Prune respects current and event references, flags lagging consumer before advancing minimum cursor and leaves active leases/permits correct.
9. Reject malicious/oversized completion payload and schema/scope mismatch before SQL mutation. No secret-bearing URLs/tokens in logs or API.
10. All existing A0/A1/A2 tests continue passing, including two independent Worker, proxy routing/global permits, cancellation, Docker shutdown and health checks.
11. Measure and report SQL/IO/WAL/lock/memory/p95 changes relative to A2 on a documented limited-resource disposable setup.

Publish compact docs/harvest-v0.1-a3-acceptance.md with actual test evidence, limits and follow-up. Update README and contracts/database.md only as genuinely implemented. Commit and push develop with SHA, no production operations.
