# Steam catalog acceptance · D3-A2-B

`steam/catalog/public` is a singleton per namespace. Grant a dedicated catalog namespace and the `steam.catalog` capability to a writer, a reader and an executing Worker. The catalog does not need a Consumer registration. It uses one-shot Jobs, with request and output schema 1 and the compiled offer `steam_v1`. Each page requests 1–64 games with DLC, software, video and hardware excluded. Results contain the exact pagination request, ordered AppIDs, bounded names, upstream modification timestamps and price change numbers.

Place `steam_catalog_api_key` only in the executing Worker's private YAML. The compiled origin and exact SDK request URI are checked before acquiring a permit. The Worker adds `X-WebAPI-Key` only to the admitted HTTPS wire request. The key is absent from the Job, control-plane request and observation. Configure a catalog provider bucket and an account bucket with a UTC daily limit. If a key is shared with other official roles, use one account bucket to enforce the combined hard budget. Keep the permitted namespace separate from production Game change streams.

Goose migration `00007` adds at most three Observation IDs to an Attempt. Authorized `GET /api/v1/jobs/:id` has an optional `confirmed_results` array for the accepted Attempt. Material results retain their immutable Job/Attempt IDs. Unchanged results reference those same records without generating a new change event. If retention removes a non-current record the reference is omitted. Consumers must require proof before committing work. Storefront details now optionally include allowlisted ESRB/PEGI codes, explicitly present minimum age and bounded numeric descriptor IDs. The existing request and output schema remain version 1.

`task check` and `TestSteamCatalog` passed locally. With PostgreSQL 18, a real Harvest Server, two independent Workers and simulated CONNECT/SOCKS5 routes, eight catalog Jobs issued eight completed permits. Two accepted pages created material Observations, repeated acquisition linked the original immutable Observation, and malformed continuation, oversized/malformed responses, 401 and 429 could not produce an accepted page. The test verified the private key reached the expected TLS endpoint in a header, never appeared in Job parameters or process logs, and did not escape the configured proxy route. The 401 also set the persisted account cooldown. The full regression and Docker run are tracked in [Harvest develop Actions](https://github.com/librecosta/harvest/actions/workflows/check.yml?query=branch%3Adevelop).

Valve documents the [catalog endpoint](https://partner.steamgames.com/doc/webapi/IStoreService) and [API-key header](https://partner.steamgames.com/doc/webapi_overview/auth). Outbound requests and Steam credentials in the test are synthetic. Real Steam compatibility, account provisioning and production throughput remain to be verified.
