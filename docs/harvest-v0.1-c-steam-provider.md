## 1. Goal / first-release scope

Implement Harvest's second **production-executable Provider**, `steam`, without any dependency on GoFurry Site/Game entities, business tags, moderation rules or CN/INTL publication. The raw source identity is positive uint32 `Steam AppID`; Harvest Target natural key remains `steam.app`. Use the maintained steam-go SDK to perform three read-only compiled capabilities:

| Capability | SDK method / upstream | Typed result |
|---|---|---|
| `steam.details` | `client.Web.Storefront.GetResolvedAppDetails(ctx, appID, *GetAppDetailsOptions)`; undocumented Storefront appdetails | locale/store-country scoped details, release, price/availability and verified media *links*, with missing/partial correctness |
| `steam.news` | `client.API.SteamNews.GetNewsForApp(ctx, appID, opts)`; documented `ISteamNews/GetNewsForApp/v2` | bounded news items with source GID, publisher/feed, published-at, title, safe URL/excerpt, optional limited tags |
| `steam.players` | `client.API.SteamUserStats.GetNumberOfCurrentPlayers(ctx, appID)`; `ISteamUserStats/GetNumberOfCurrentPlayers/v1` | time-specific integer count, source status and observed timestamp, including real zero |

Do not implement Steam user inventories, community profile crawling, Market trading, SteamDB scraping, A2S server scanning, screenshot downloads, browser automation, Store Reviews, purchase flows, OAuth user login, full partner events or full release/price analytics in V0.1-C. Storefront adjacent partner events are a **future explicit capability**, not an automatic fallback for failed ISteamNews. Do not make commercial or furry/adult classification assertions.

## 2. Data identity, params and scope

- Reuse the current `steam.app` canonical numeric target and UUIDv7 Target/Job/Attempt. Every operation binds the requested AppID to its stored Target before dispatch and validates the response *again* before Observation acceptance.
- `steam.details` request: **one language and one store country per Job**, from strict allowlisted values, for example `schinese/english` and `CN/US/HK`. Normalize Steam language aliases and country codes at the boundary without inventing translation. A country affects prices and catalog availability; language affects presentation. `Scope.Locale`, `Scope.Region`, `Scope.EgressRegion` and access namespace are distinct. **Do not issue six multi-region/locale HTTP requests inside one unbounded Job**; create explicit schedules/jobs for each needed scope. Limit initial supported choices, expand by versioned validation.
- `steam.details` result uses **independent scoped segments**: localized descriptive metadata vs country-specific price/availability vs bounded media URL summaries (if reliable). Avoid requiring all fields to appear in every Store response. `GetResolvedAppDetails` validates `Data.SteamAppID`, and a mismatched/ambiguous/unsuccessful envelope **fails closed**, never attaches data from another app. Preserve safe source provenance and schema versions.
- Price: keep currency + Steam integer minor-unit amounts (initial/final), explicit discount and state. Distinguish `is_free=true`, absent price for unreleased/non-salable/region-restricted, regional no-data, and an actual 0 promotional price. Missing `price_overview` is **not** evidence of a free app or price=0; avoid manufacturing historical release dates or converting vague release text into exact timestamps. Price/availability must not clear previous good values on transient upstream gaps; authoritative state transitions only with documented evidence.
- Multi-language/region results from different Jobs update only their own semantic scope; one failed locale or storefront region never overwrites the other. If a price segment is keyed independent of locale, enforce deterministic single-writer derivation and prove no cross-locale collisions; simpler option is to keep price scoped to the exact country+locale request and leave consolidation to consumer. Do not conflate proxy exit country and Steam `cc` store country.
- `steam.news`: validate returned AppID, bound count (e.g. <=10 per Job), cap upstream `maxlength` and normalized excerpt, preserve stable GID/ID and feed identity, published timestamp (not interpreted as collection time), safe canonical URLs and one bounded versioned collection observation. Deduplicate repeated GIDs; source news that later drops out of a short feed is **not** authoritative deletion of old events. No full HTML/article archiving by default.
- `steam.players`: require source result/success evidence; `player_count=0` is a valid sample when source confirms success. Invalid result, absent value and upstream errors must not become 0. Use A3's **point-in-time sample** policy and bounded retention; never backfill missed samples with current counts. No invented peak/average from absent data.
- A3 Last Known Good, Observation, Change Stream, revisions and consumer reset are reused as-is. Normalize only safe source facts; do not persist raw Store JSON indefinitely. Keep strictly bounded payload/body/segment limits, and preserve authoritative source URL references without automatically fetching media.

## 3. SDK / Harvest transport boundary — mandatory proof before coding around it

The current Harvest `egress.Client` exposes `Do(*http.Request)` only; steam-go injects `*http.Client` through `WithHTTPClient`, builds separate TrafficClass runtimes, and may internally retry, cache or construct proxy selectors. **There must be exactly one authoritative route and one permit gate**.

- Build a narrow `http.RoundTripper` adapter backed by the current Attempt-scoped **Harvest Egress Client** (or equally safe transport injection): every outbound SDK RoundTrip invokes the guarded Egress session. Do not let steam-go wrap an alternate default/unmetered network transport, call `http.DefaultClient`, or read ambient proxies.
- Configure SDK with `WithHTTPClient`, bounded timeout/body bytes, explicit `WithRetry(0)` or tested equivalent **per class**, disable independent proxy selectors and unintended memory cache, and avoid unbounded local rate-limit settings. Harvest controls cross-Job retry, A4 global provider/account/egress buckets and proxy choice. The SDK owns endpoint shapes and typed decoding, not global quotas.
- The sdk-generated URL may contain an API key in a query parameter. All log/observer/DB paths must sanitize it, plus cookie, token and proxy credentials. Credentials remain in **Worker-local explicit YAML**, scoped to an allowed Steam account key identity; no API key in Job, central policy JSON, Observation or worker advertisement. Only use keyless documented endpoints when valid for the chosen method and source; require explicit credentials when necessary.
- **Only allowed HTTPS Steam Origins and exact capability-specific paths/methods** are valid: Storefront `/api/appdetails`, News `/ISteamNews/GetNewsForApp/v2/`, Players `/ISteamUserStats/GetNumberOfCurrentPlayers/v1/` (verify SDK's actual method path and trailing slash from source). Check immutable target AppID in generated query; reject methods/paths/hosts, arbitrary redirects and external SDK helper calls not in this contract. No unrestricted `RawHTTPRequest` path.
- A2/B1 FixedOrigin permit now indexes approved Origins and does not by itself understand **AppID-bearing query parameter**; extend only the narrow attested origin/path/query/target binding if essential. Keep Permit idempotency, SSL chain verification, SNI, direct/proxy strictness and A4 routing revision fencing. No extra public fetch API.
- Every SDK-requested network RoundTrip including any redirect/HTTP retry must acquire its own Permit, even if an SDK implementation changes. Never allow N SDK retries multiplied by Harvest Job retries. Verify actual on-wire count and that a blocked 429/403 triggers cooldown rather than proxy/key rotation around upstream refusal.
- `steam-go.Client.Close()` calls CloseIdleConnections on its HTTP clients. Do not close a shared Harvest Worker pool when an individual Attempt SDK client finishes. A small adapter that does not own the shared transport is preferred; verify connection reuse and no goroutine leaks across many Jobs. If the current SDK API *cannot* safely express the needed ownership/budget, make **one small backward-compatible upstream change** in `gofurry/steam-go` under its v1 compatibility policy, with separate tests and explicit report. Do not fork or silently alter SDK behavior and do not modify other repositories until the actual gap is demonstrated.
- The current Harvest individual network Permit TTL is bounded (5 seconds at A2/B1) while an SDK call can have a longer timeout. Verify via local and opt-in slow-proxy fixtures; when legitimately necessary, introduce a **small, measured, bounded** extension of Permit / attempt deadlines with regression tests. Never extend the clock behind the control plane or use unmetered fallback. Long quota waits must defer Job rather than exhaust bounded attempts or spin.
- Keep the existing Fiber lifecycle, Worker cancellation, lease generation/fencing, PostgreSQL operational policy and Client TLS trust. No separate SDK-managed authentication or proxy pool.

## 4. Rate limits and policy persistence

The June 7 2026 Storefront experiment in steam-go observed approximately 220–230 appdetails attempts before 429 in one configuration; **228 successes in a run is not an official universal 5-minute limit**. Treat it as empirical, IP/traffic-profile-sensitive and potentially changed.

Storefront initial default **operator-supplied PostgreSQL policy suggestion**, not an automatic unconditional source cap:
- shared Storefront/AppDetails traffic bucket `burst: 1`, `per_minute: 30`, `concurrency: 1` (about 150 attempts per 5 minutes steady state, below 80–85% of the observed 228). After real validation consider at most `per_minute: 36, burst:1` as an *operator decision* (about 180/5min); never hardcode an alleged 228 official rate into the Provider.
- keep independent buckets for `steam.details` Store traffic and `steam.news/steam.players` official API traffic. Where actual account/key, source IP or upstream quota is shared, **link the same account/egress/provider bucket** so multiple Workers cannot each spend an entire budget. Do not treat proxy endpoint IDs as necessarily distinct public IPs.
- Steam player sampling may consume official API quotas frequently; **daily key limits are NOT guaranteed by Harvest's current per-minute Token Bucket**. If a known daily cap applies, implement a small persistent UTC/issuer-time daily hard budget (without adding a new service or new config center), with tests for restart/boundary/concurrency; or defer/disable high-frequency player schedules until the hard budget is verified. Do not claim daily enforcement if none exists.
- Respect 429 and Retry-After; for 401/403 and block-detected responses apply conservative account/source cooldown and require review if sustained. No proxy/key rotation to evade a block. Record sanitized quota counters and source feedback.
- One AppID *per* country+locale details request. If an operator wants 2 languages × 3 countries, budget **up to 6 Store requests** and schedule appropriately; a shared 30/min pool across all apps prevents burst multiplication. No surprise background Store events or reviews.
- Initial operator-controlled schedule recommendations (NOT auto-created): details 24h, news 6–12h for priority apps, players 30–60min only for selected apps; inactive/archived apps get much lower frequency or paused schedule. Respect the A1 point-in-time missed-slot policy for player samples. Avoid eager historical backfill and default 30min sampling of every app.

## 5. Source-specific completeness, response semantics and budgets

- `steam.details`: Source tier `observed Storefront`, not an officially guaranteed Steamworks API. Treat `success=false`, absent `data.steam_appid`, mismatched AppID and schema drift as unavailable/invalid, not authoritative withdrawal. Return descriptive fields with Unicode/HTML sanitization and safe optionality; keep Steam-returned media URL references (header, capsule, screenshots, movies) as links only. Preserve developer/publisher/platform/language/category/genre facts if source confirms them. Do not guess region content, ratings or date.
- `steam.news`: Source tier `official ISteamNews API`, bounded 1–10 new items per response, return stable GID and metadata. Count 0 is a verified empty *response page*, not proof every historical news item is deleted. Use stable event IDs to avoid redundant Event updates when the current list window scrolls; if B3 needs a small additional distinct news-item result identity/segment, add it only when deterministic tests prove necessity.
- `steam.players`: Source tier `official ISteamUserStats API`, exact source success + integer >=0; UTC observed_at refers to acquisition time. Number is sample, not a persistent guarantee of current online count.
- For all: strict source ID validation, upstream status and blocking vs transport failure classification, partial scopes, safe provenance, stable schema versions, bounded normalized JSON, sanitized external links. User-supplied fields do not include HTTP method, arbitrary host/path, raw header or proxy selection.
- A3 event retention (default ~14d), history (~30d) and current-result protection apply. News data and details avoid full raw archival; player samples are never deduplicated away merely because value repeats. Add source-type observability for skipped/incomplete scopes and per-Capability request counts.

## 6. Test environment and security

Use deterministic local Storefront + Official API fixtures with `steam.WithBaseURL`/`WithStorefrontBaseURL` **only inside the test binary**, never exposed as free-form production config. Use disposable PostgreSQL 18 and two independent Harvest Worker processes, with direct, HTTP CONNECT, HTTPS CONNECT and SOCKS5 proxies as relevant.

Prove:
1. Register Steam Target, schedule/submit a Job, SDK call -> real guarded HTTP request -> Permit -> typed scope Observation -> Current -> Change Stream -> consumer snapshot/ACK. All production capabilities advertise executable only after successful tests.
2. AppID mismatch, duplicate ambiguous appdetails keys, false success, missing optional price, a verified free game, 0/discount/price and region/language change semantics do not cause wrong identity or data erasure.
3. Partial Store locale/region failure leaves last good unaffected; country/language requests remain separate. Correct country/egress scope and no secret URL persisted.
4. News AppID mismatch, repeated GID, empty feed vs removal, invalid timestamps, pagination limit, source drift and long article content return safely bounded results.
5. Successful players count **zero** becomes a valid point-in-time Observation; `result!=1`, null/invalid and timeouts never become 0. Repeated equal samples persist; missed schedules stay gaps.
6. 6 Store requests for six region/locale combinations debit six permits; two Workers on same account and effective exit cannot exceed one shared quota; a retry/redirect also debits when it reaches wire. 429/403 does not cause proxy cycling; cap/retry/backoff and lease behavior remain correct.
7. A4 live quota/routing changes, held claims, stale leases, worker kills, result replay, cancellation/SIGTERM, DB outage and lost control plane preserve safety. No unmetered SDK fallback, even if HTTP_PROXY env is set.
8. SDK client injection/Close does not close another Attempt's network connection or leak transports; repeated Jobs reuse Worker proxy connections. Check with race detector and real two-Worker stress.
9. No credentials, full query-with-key URLs, cookies or proxy passwords in logs, errors, Observation/current/change events or tests. TLS validation and fixed-host/endpoint restrictions are enforced even on redirects.
10. Correct resource budgets: throughput (attempts/min and 5min window), permit p95, SQL statement/WAL additions, connection pressure, heap, normalization CPU and egress bytes. Report measured local numbers, no invented production SLA.
11. `task check`, `go test -race ./...`, A0–B2 integration regressions and Steam fixtures pass on supported CI; Compose + Linux ARM64 image build. Live Steam smoke test is explicit, **opt-in only**, with low request count and no secrets in artifacts.
12. An optional limited 5-minute rolling-window assertion can check that `per_minute:30,burst:1` stays conservatively below the empirical 228 limit; clarify token bucket vs hard time-window semantics. Do not mislabel per-minute control as a Steam-official guaranteed rolling-window limiter.

## 7. Operational implementation constraints

- A4 PostgreSQL policy is the only authority for network quotas/route associations and supports online revisioned updates. Worker-specific Steam API key and proxy credentials reside **only in explicit, gitignored Worker YAML** (private UID/file permissions); no environment-variable overrides or secrets in the DB-owned policy.
- No auto-created schedules for a registered Steam App. Operator/consumer explicitly chooses cadence and scopes. No SDK rate limiter acting as the sole global guard. Make source classes and policy buckets visible through the existing authenticated `/api/v1/operations/status`, with sanitized labels, results and retry reasons; don't add a new dashboard.
- No unnecessary provider-specific SQL tables or GoFurry backend coupling. Keep Router url.go route inventory and Fiber graceful hooks. Do not add Redis, a queue service, browser automation or new repository.
- The SDK uses standard `encoding/json` internally while Harvest uses Go 1.27 `encoding/json/v2` at its own boundary; accept a small typed conversion layer, not duplicate steam-go endpoint parsers.
- Keep release notes/README concise, English project code and docs as established; new provider schema changes use explicit versioning and data migration only if necessary.
